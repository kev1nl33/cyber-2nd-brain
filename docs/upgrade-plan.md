**目标：** 让第二大脑看起来像一个发光的中心物：色彩与字体收敛到一处、全画面一层极淡的颗粒、切换层级时节点向中心收拢再展开、背景中心一圈绿色的慢速发光环。保持零构建、零依赖，更新仍是改文件后直接上传 R2。

**方案：** 乙，以丙为第一阶段。三期依次上线，每期都可以单独回退。只改第二大脑这一个页面，不动博客正文页。

**技术约束：** 原生 HTML / CSS / ES 模块，不引入任何新依赖，不加构建步骤，不改数据结构。绿色保留现有 `#7ef2b0`，只借鉴「单一光源」的用法。手机访问频率按「中」规划。

**分支与提交：** 全部工作在 `feature/second-brain-visual-phase1` 上进行，不直接提交到 `main`。第一个提交只有这份计划文档，不含任何代码；之后的提交才按第一期、第二期、第三期分别落代码，每一期的提交可单独回退。

### 颗粒怎么做

用一张内联的 SVG 做平铺的噪点，不用 Canvas，不用 JS，不占用任何帧。噪点只生成一次，之后由浏览器平铺，手机上没有持续开销。

```css
.grain {
  position: absolute;
  inset: 0;
  z-index: 0;
  pointer-events: none;
  opacity: 0.05;
  background-image: url("data:image/svg+xml;utf8,<svg xmlns='http://www.w3.org/2000/svg' width='140' height='140'><filter id='n'><feTurbulence type='fractalNoise' baseFrequency='0.85' numOctaves='2' stitchTiles='stitch'/></filter><rect width='100%' height='100%' filter='url(%23n)'/></svg>");
  background-size: 140px 140px;
}
```

几个关键点：

- `z-index: 0`，DOM 位置紧跟 `#bg-canvas`。`0` 与 `auto` 在同一个绘制层，按 DOM 顺序排在背景画布之后，所以颗粒是「背景之上、内容之下」：压不住暗角、连线、连线标签、节点、星空、顶栏底栏和浮框。不要写成 4，那会盖住连线和连线标签（两者都是 `z-index: auto`），细线和 9.5px 的小字会最先被噪点显脏。
- 定位父元素是 `.app`，不是 `.stage`。`.app` 是 `position: fixed`（`src/styles.css:57-61`），`height: 100dvh`、`overflow: hidden`，所以颗粒覆盖整个视口，也不会撑出滚动条。`.stage` 没有 `z-index`，不创建层叠上下文，颗粒不需要穿透任何中间层。
- `pointer-events: none`，点击穿过去。
- `stitchTiles='stitch'` 让平铺接缝看不出来。
- 透明度从 `0.05` 起。若在 1440×900 上看不见，最多加到 `0.08`；若能看出颗粒压住了节点标签，就降到 `0.04`。不要超过 `0.08`。
- 这一层没有动画，所以动效开关对它没有作用，也不需要降级。

### 不引入任何新依赖

不加 npm 包，不加构建工具，不加字体文件，不加第三方脚本。颗粒是一段内联的 SVG，浏览器原生支持。

## 第二期：节点对焦入场 + 切换层级时的收拢展开

这一期只改动画的节奏，不改布局算法，不改数据，不改相机的适配规则。

### 效果

点一个主题脑时，现在的画面不是立刻换掉，而是：上一层独有的节点先向旧层中心收拢、变小、变淡；新一层独有的节点（例如问题节点）先等一拍，约三分之一秒后再从新层中心向外展开、变亮。前后两层都有的节点（总脑与其余四个主题脑）不收拢、不淡出，只缓动到新位置，因为现有布局在主题层仍保留它们，本期不改 `layout.js`。整个过程约半秒，速度平稳，不弹跳。返回上一层时相同：先收回来，再展开去。

点一个步骤、打开浮框、展开来源这些不换层的操作，仍然是现在的样子：节点原地高亮，画布不移动。

关掉动效后，切换层级立刻到位，没有收拢、没有等待。

### 现状与要改的地方

现在的入场已经做了一半。`src/scene.js` 的 `setLayout()` 里，新节点从它的父节点位置出生（约第 153 行），离开的节点向父节点移动并在 280 毫秒后被删除（约第 172 行）。缺的是两件事：

1. 离开和进入同时发生，两层节点叠在一起，看不出「先收后放」。
2. 旧节点是向各自的父节点飞，不是向画布中心收拢，所以没有「汇聚到一点」的感觉。

要改成：只有换层时才走收拢；收拢期间新节点先不出现；离开的节点收拢到旧层的中心，新节点从新层的中心展开。这里的「两个中心」指旧布局与新布局各自中心节点的**目标坐标**，不是节点当前正在移动的位置；两者可以重合（例如总览的总脑与主题层的开发脑目标都是 (0, 0)）。从总览进入开发时，问题节点从开发脑的新目标位置展开；其余四个主题脑在两层都存在，按共有节点处理。

### 改哪些文件

- **改 `src/scene.js`。** 给 `setLayout()` 加一个参数 `collapse`，默认为假，这样现有的调用不变。

  当 `collapse` 为真且动效开着时：

  1. 分别找出旧层和新层的中心。旧层中心是离开前那一层里 `role` 为 `theme-active` 或 `core` 的节点；新层中心是新布局里同样角色的节点。哪一层找不到，就用画布中心（0, 0）。
  2. 所有即将离开的节点，把目标改成旧层中心的位置，尺寸改成原来的一半，并加上 `.is-exiting`。这样它们会沿着现有的缓动一起收拢。
  3. 新节点先创建但不显示：加一个类名 `.is-held`，样式为 `opacity: 0`，出生位置取新层中心而不是父节点。记下一个解锁时间，取 `performance.now() + 340`。
  4. 在 `frame()` 里，时间一到就去掉 `.is-held`，新节点从新层中心展开到自己的目标位置。这一步复用现有的 `EASE_TAU`，不加新的动画库。
  5. 旧节点的删除延迟从 280 毫秒改为 420 毫秒，保证收拢完才消失。

  前后两层都存在的节点，比如从总览进入某个主题时那个被点中的主题脑本身，不走收拢也不走展开。它一直在画布上，只是从旧位置缓动到新位置，不加 `.is-exiting`，也不加 `.is-held`。现有代码已经是这个行为：`setLayout()` 碰到已经渲染过的节点只更新它的目标位置。这里要做的是保证收拢逻辑不要把它也当成离开的节点。

  当 `collapse` 为假时：走现在的路径，不加 `.is-held`，离开的节点保留现有的 280 毫秒删除延迟；只有动效关闭（`instant` 为真，包括系统「减少动态效果」）时才立即移除。

  暂存（`.is-held`）期间，新节点的位置与尺寸都冻结在出生值，`frame()` 不推进它们，解锁后才开始缓动；只隐藏而不冻结会让节点在隐藏期间提前飞出去。

- **改 `src/styles.css`。** 只加一条规则：

```css
.node.is-held .node-art,
.node.is-held .node-label {
  opacity: 0;
}
```

  并在现有的 `.app[data-motion="off"]` 规则里补上 `.node`，使关闭动效时位移也没有过渡。注意节点位移由 JS 缓动驱动，`.node{transition:none}` 管不到；关闭动效（含系统「减少动态效果」）必须经 `scene.setInstant()` 走即时路径。现有规则已经关掉了 `.node-art` 与 `.node-label` 的过渡，这里只需确认它仍覆盖到新增的状态。

## 第三期：发光环背景（Canvas 2D），带静态降级

这一期加一个发光的中心物。它是一圈绿色的光，不是引力透镜，不是黑洞，没有吸积盘，没有光线弯曲。

### 效果

画布正中央有一圈柔和的绿色光晕，亮度低于任何一个节点。光晕中间是空的，能看见后面的网格与星空。光沿着环缓慢流动，一圈约十几秒，不闪烁、不跳动。总脑或当前主题脑压在这圈光上面，光是背景，不与脑争抢注意力。

光环固定在屏幕中心，不跟随相机。拖动、缩放画布时，节点和网格在移，光环留在原处。这样它一直是背景，不会在拖动时跟着节点一起跑、抢走注意力。它要不要改成跟着总脑走，见文末「需要老板决定」，做完看效果再定，实施时先按固定在屏幕中心做。

关掉动效后，这圈光停在当前帧，不再流动，也不消失。

手机上这圈光更小、更暗，并且画得更粗，以换取不卡。手机访问频率按「中」规划，降级仍然要做，但不再要求真机验证。

### 改哪些文件

- **新增 `src/glow.js`。** 一个只负责画光环的模块，约一百行。导出一个函数 `createGlow(ctx)`，返回 `{ frame, resize }`。

  画法，全部用 Canvas 2D 的径向渐变，不用着色器，不用 WebGL：

  1. 中心取画布中心，半径取较短一边的约四分之一。手机（较短边小于 560）再乘以 0.8。中心用屏幕坐标，不加上相机的偏移，所以拖动画布时它不动。
  2. 光环由两层组成。外层是一个很宽、很淡的径向渐变，从透明到绿色的淡色再回到透明，宽度约为半径的一半，这一层完全不动。内层是一圈细线，宽度 1.5 像素，颜色用 `--green` 的值，透明度约 0.35。
  3. 外层光晕预渲染到一张离屏画布，在 `resize()` 里画一次。每帧只把这张离屏画布整幅贴上去，再另画移动的亮弧。这样每帧的开销只剩亮弧那一点。
  4. 流动用一段沿环移动的亮弧。把环分成约 48 段短弧，每段的亮度由它与一个缓慢移动的角度之间的距离决定，远的暗、近的亮。角度每秒增加约 0.4 弧度，一圈约 16 秒。这是唯一随时间变化的量。
  5. 分辨率跟着 `background.js` 走，设备像素比上限取 2，不另外设 1.5。手机上把段数从 48 降到 24。
  6. 颜色从 `tokens.css` 读，不写死。读的时候加 `trim()`，因为自定义属性的值带前导空格：

```js
const green = getComputedStyle(document.documentElement).getPropertyValue("--green").trim();
```

     读到的是十六进制 `#7ef2b0`，而渐变需要带透明度的形式。把每两位拆开转成数字，再拼上透明度：

```js
function withAlpha(hex, alpha) {
  const n = parseInt(hex.slice(1), 16);
  const r = (n >> 16) & 255;
  const g = (n >> 8) & 255;
  const b = n & 255;
  return `rgba(${r}, ${g}, ${b}, ${alpha})`;
}
```

     这样 `withAlpha(green, 0.1)` 得到外层光晕用的淡色，`withAlpha(green, 0.35)` 得到细线的颜色。只在 `resize()` 里读一次，不要每帧读。

  清除策略只有一种，不要混用。光环画在现有的 `#bg-canvas` 上，由 `background.js` 统一清屏：它的 `frame()` 每帧开头已经用 `clearRect` 把整幅清掉，然后画网格、微粒和 0/1。光环排在这些之后画，直接画在清空后的画布上，不自己清任何区域，也不用 `lighter` 这种叠加方式。现有的清空是整幅重画，不是半透明拖尾，所以不需要给光环单独准备一块画布，`index.html` 也不用加新的 `<canvas>`。

- **改 `src/background.js`。** 两处：
  1. 引入 `createGlow`，在 `resize()` 里调用它的 `resize()`，让离屏光晕按新尺寸重画。
  2. 在 `frame()` 的末尾调用光环的 `frame(dt, motion)`。`frame()` 已经有 `motion` 参数（第三个参数），不用新增，也不用改它的签名。微粒、数字和光环都按这同一个参数决定动不动：为假时角度不增加，光环画出来但停住。

- **改 `src/app.js` 的主循环。** 以「动效关闭后只在转换帧补画」为准，不要让背景在动效关闭时仍然每帧重画。

  现在的写法是只有 `state.motion` 为真才调 `background.frame()`（约第 775 行）。改成：动效开着时每帧都调；动效关着时，只在下面四个时机各补画一帧，其余时候不调。

  1. **开转关。** `applyMotion()` 把动效从开改成关的那一次，补画一帧，让光环停在关闭的那一刻。
  2. **窗口缩放。** 现有的 `resize` 监听已经调 `background.resize()`，在它之后补画一帧，否则光环会停在旧的位置和尺寸上。
  3. **页面重新可见。** 监听 `visibilitychange`，当 `document.hidden` 从真变假且动效关着时补画一帧。切到后台期间不画。
  4. **光环初始化。** 页面首次进入、光环刚创建完时补画一帧。否则当系统开启「减少动态效果」、动效从一开始就是关的时，画布上会一直没有光环。

  时间步长不用改。`tick()` 里已经是 `Math.min((now - last) / 1000, 0.05)`，切到后台再回来时，单帧最多推进 0.05 秒，角度不会跳变。保持这一行，不要在光环里再写一个限制。

### 静态降级

降级不是换一张图，而是停止计算：

- 动效关闭，或系统开启「减少动态效果」：按上面的补画时机画一帧，角度固定不动，之后不再进入绘制。画布上留着这一帧，光环仍在，只是不流动。
- 页面切到后台（`document.hidden` 为真）：同样停止，回来时若动效开着则恢复。
- 若 `canvas.getContext("2d")` 失败：不画光环，其余页面照常工作。不报错，不阻断加载。

## 可选：复用 Voiden 的 WebGL 着色器与渲染器（只做可行性验证，不实施）

这一节不写代码，不改文件，不上线。它回答三个问题：这两个文件能不能脱离 React 与 GSAP 单独跑、手机 GPU 大概要多少、放在图谱后面会不会影响读信息。结论基于对 `.voiden-ref/` 的只读核实，不是估计。

### 能不能脱离 React 与 GSAP 单独运行

能，而且已经有人做到了。`.voiden-ref/blackhole-port.js` 就是这个结果：它是一个不依赖 React、不依赖 GSAP 的原生 ES 模块，导出 `createBlackHole(canvas, options)`，内部自己跑 `requestAnimationFrame`，自己处理窗口尺寸、页面可见性与 WebGL 上下文丢失。动效关闭时它画一帧就停，与本计划的降级要求一致。

原始的两个文件本身也几乎不依赖这两个库：

- `shader.ts` 里的着色器是纯字符串，顶部没有任何导入，只依赖 WebGL1 的内置函数。
- `renderer.ts` 的逻辑只依赖 WebGL 接口。它的类型导入来自 `store.ts`、`camera.ts`、`shader.ts`，而这些文件才是与 React、GSAP 绑在一起的部分：`store.ts` 管理页面滚动、菜单、页面切换与鼠标吸引，`motion.ts` 直接导入 GSAP。

所以「能不能单独跑」这个问题已经有肯定答案：能。真正的问题不在运行，而在下面两条。

### 手机 GPU 占用的估计

这个着色器的代价几乎全部在光线追踪上。`shader.ts` 第 47 行定义 `MAX_STEPS 170`，第 384 行起每个像素最多跑 170 步积分，每一步都有幂运算与开方。这是一个每像素、每帧都要付的代价，不能靠减少物体数量来降低。

移植版已经做了三件节省的事：设备像素比上限 1.5，整张画布上限约 150 万设备像素（`MAX_DEVICE_PIXELS = 1500000`），并使用 `powerPreference: "low-power"`。按这个上限算，一帧最多约 2.5 亿次积分步。

对照手机：一部 390×844、像素比为 3 的手机，原始分辨率约 100 万物理像素、约 900 万设备像素。被上限压到 150 万后，画面会被浏览器放大约两倍以上。在一个本来就模糊的背景上这个放大看不出来，但即使如此，每帧仍是一亿次量级的浮点运算。

判断：在桌面上可以接受；在按「中」规划的手机访问上，风险仍然高。它会与图谱本身的绘制、缓动、星空抢同一块 GPU，而且即使用户只是在读一条思考链、背景完全没有变化，这个代价仍每帧都在付。这正是本计划把第三期做成 Canvas 2D 光环的原因：同样的「中央一个发光物」，代价差几个数量级。

若将来真要验证，唯一靠谱的方法是在真机上看帧时间与发烫，而不是再推导一次。本计划不做这件事。

### 放在图谱后面是否影响信息可读性

会，而且这个冲突来自它的设计本身，不是参数没调好。

这个着色器画的是一个黑洞：中央是一块完全黑的影子，周围是亮度很高的吸积盘，颜色从深棕到暖白（`shader.ts` 第 101 行起的色板），还有星空、星系带与极向喷流。而第二大脑的信息正好也集中在画布中央：总脑、当前主题脑、思考主线都在中间。

两个具体问题：

1. 黑洞的影子会把中央那一块背景变成纯黑，压在总脑下面。即使把黑洞缩很小，它仍是一个强焦点，与「画面只有一个主焦点」的现有约定冲突。
2. 吸积盘是暖色且亮度高，而本页面用暖金色表示阶段理解、用暖白色表示星空。一圈亮暖色放在背后，会让人把装饰误认成数据。这违反现有视觉约定：装饰性的线不能冒充真实的数据关系。

老板要的是「一个发光的中心物」，不是引力透镜黑洞本身。用这个着色器去追求前者，是用一个远超需求的工具去做一件简单的事，并且付出可读性的代价。第三期的 Canvas 2D 光环已经覆盖这个目标。

### 结论

技术上能接入，代价与收益不匹配。不建议实施。若以后要重新考虑，前提是先在真机上量过帧时间与发烫，并且确认黑洞的影子与暖色光盘不会压过中央的脑与思考链。在那之前，不要动 `.voiden-ref/` 里的任何文件。
