## 1. 项目是什么，要达到什么

### 背景

老板有一个个人网站 https://aikevin.dpdns.org/（"计划李"），其中有一个自己做的页面叫**第二大脑（Cyber Brain）**：深色背景、绿色线稿，中心是"数字大脑"，周围是 5 个主题脑（投资、创作、开发、阅读、个人成长），每个主题下是问题，问题下是思考步骤和来源引用。页面带图例、缩放控件和一个"动效开关"。

老板看到两个很喜欢的模板（Voiden 与 Norrvik，均为 Modulify 平台出品），希望自己的第二大脑也有那种**暗、慢、克制、有一个发光的中心物**的质感。老板已购买 Voiden 的授权并下载了源码。

### 一句话目标

让第二大脑看起来像一个**发光的中心物**：色彩收敛、画面有一层极淡的颗粒、切换层级时节点向中心收拢再展开、背景中央有一圈缓慢流动的绿色光环。

### 三期交付

| 期 | 做什么 | 老板会看到什么 |
|---|---|---|
| 第一期 | 设计令牌收敛（颜色、字体、布局变量集中到一个文件）+ 一层极淡的 SVG 颗粒 | 画面几乎不变，只多一层隐约的胶片颗粒 |
| 第二期 | 切换层级时，旧节点先向中心收拢，新节点再从新中心展开 | 切换有"呼吸感"，不再是生硬地换掉 |
| 第三期 | 背景中央加一圈缓慢流动的绿色光环（Canvas 2D），带静态降级 | 有一个发光的中心物 |

第一期几乎看不出变化，是在**打地基**。看起来"和原来一样"恰恰说明做对了。

### 不在范围内

- 博客其他页面（米白底、硬黑边、橙色的新野兽派风格，与第二大脑相反，强行统一两边都会受伤）
- 把 Voiden 的黑洞着色器搬进来
- Norrvik 的设计语言（Fig. 编号标签、HUD 式读数、数据图表区）只作为以后的灵感，不在这三期里做
- 编辑、同步、自动导入等功能（项目当前约定这一轮只做浏览和追溯）

## 2. 为什么这样做：思路与关键决策

这一节记录的是**判断过程**。以后遇到没写到的情况，按这里的思路推断，而不是随意发挥。

### 2.1 为什么要先评估，而且评估阶段只读

把现成的酷炫模板搬进自己的老站，最大的风险不在样式，而在**两边的技术栈能不能对上**。如果跳过评估直接动手，常见结果是做到一半发现框架不兼容，推倒重来。评估阶段严格只读，是为了让这个判断不被"已经改了一半"的沉没成本干扰。

### 2.2 评估的结论（已完成，依据来自对源码的只读核实）

**Voiden 是什么：**
- Next.js 16.2.3（Pages Router）+ React 19.2.4 + Tailwind v4 + GSAP 3.15.0
- 视觉核心是**自己写的 WebGL1 + GLSL 片元着色器**，不是 Three.js。它每帧对每个像素做施瓦西光线追踪（最多 170 步积分），画一个黑洞
- 整个页面是一个**挂载一次、跨页面不重载的黑洞画布**，每个路由只是给"相机"指定观测位置，滚动只是在两个位置间插值
- 它依赖服务端：`output: 'standalone'`，有真实的 API 路由（SQLite、发邮件、限流），内容走 ISR。**不能导出成纯静态文件部署**
- 源码没有 LICENSE，`package.json` 里 `"private": true`，是平台生成的私有项目

**第二大脑是什么：**
- **零依赖、无构建步骤**的静态单页：原生 HTML + ES Module，Canvas 2D 背景 + SVG 连线 + HTML 节点，全部手写
- 它不在博客仓库里。博客是 Cloudflare Pages；第二大脑的文件**手动上传到私有 R2 桶 `second-brain-private`**，由博客仓库里的登录门卫 `functions/second-brain/`（cookie + PBKDF2）按路径取出
- 页面是固定视口（`overflow: hidden`，`100dvh`），**没有页面滚动**，靠拖拽和滚轮缩放探索图谱

### 2.3 关键决策及理由

**决策 1：选方案乙（用原生技术重写效果），以方案丙（设计令牌收敛）作为第一阶段。不移植 Voiden 的代码。**

理由，按重要性：
1. **页面模型对不上。** Voiden 最出彩的三个效果（相机推移、对焦显现、页面坍缩过渡）都靠滚动或换页触发，而第二大脑不滚动，这些效果没有地方挂。
2. **会破坏每天走的更新流程。** 现在更新笔记就是改文件、上传 R2，中间没有构建。移植意味着引入打包，还要重新验证"门卫按原始路径取文件"的约定。
3. **手机端风险。** 黑洞着色器每帧每像素最多 170 步，自己还要在运行时自降画质，叠加在图谱本身的绘制上，手机会吃力。
4. **老板要的观感，原生重写基本能给到。** 真正值钱的是"暗、慢、克制、一个发光的中心"，而第二大脑本来就在做这件事。
5. 授权：老板已购买授权，所以授权不是障碍。但**即使授权没有问题，上面四条技术理由仍然成立**，所以前两期用原生技术重写，不拷贝 Voiden 的代码。

**决策 2：要的是"一个发光的中心物"，不是"引力透镜黑洞"本身。**

黑洞着色器放在图谱后面会有两个冲突：中央一块纯黑的影子会压在总脑下面，成为第二个强焦点；吸积盘是暖色高亮，而页面用暖金色表示"阶段理解"、暖白色表示星空，一圈亮暖色会让人把装饰误认成数据。所以用 Canvas 2D 做一圈绿色的光环，代价差几个数量级，目标一样。

**决策 3：保持零构建、零依赖。** 更新笔记继续是"改文件直接上传 R2"。任何会在这条每天走的路上加一步的方案都不要。

**决策 4：只改第二大脑页面，不动博客正文页。**

**决策 5：保留绿色 `#7ef2b0`，只借鉴 Voiden "单一光源"的用法，不借它的暖金色谱。**

**决策 6：手机访问频率按"中"规划。** 降级要做，但不要求真机；低端性能用 Chrome 开发工具的 **4 倍 CPU 节流**，在 390×844 视口下验证。

**决策 7：光环固定在屏幕中心，不跟随相机。** 这样它一直是背景，拖动时不会跟着节点跑、抢走注意力。是否改成跟着总脑走，第三期做完看效果再定。

**决策 8：分三期，每期可独立上线、独立回退，按风险从低到高排。** 光环风险最高，放最后。

**决策 9：每期结束都停下来等老板亲自看。** 视觉观感、手机手感，自动检查验证不了。

### 2.4 思路上的几条原则

- **借鉴语言，不搬代码。** 想法不受版权保护，实现要用自己的技术重写。
- **"酷"之前先问"为什么酷"。** 老板喜欢模板的整体感，不等于能说出具体哪一点。先拆解，再挑选。
- **能量化的要量化。** 验收标准必须是能检验的，"看起来不错"不算。
- **风险最大的步骤单独停下。** 令牌迁移最容易出隐蔽问题，所以做完要停下核对，不要连着做完。

## 3. 项目现状：两边的技术事实

以下是写指导文件时核实过的事实。**代码有变化时以代码为准，并告诉老板。**

### 3.1 第二大脑页面

位置：`~/Documents/03-Github/Cyber-2nd-Brain`（**原项目目录，不要在这里直接改**）。

- 入口 `index.html`。三个数据脚本用相对路径加载：`./private-data/flomo.js`、`./private-data/thoughts.js`、`./private-data/lessons.js`，然后 `<script type="module" src="./src/main.js">`。**这些路径必须原样保留**，门卫按原始路径取文件
- `src/` 主要文件：`app.js`（主循环、路由、动效开关）、`scene.js`（节点与缓动）、`background.js`（Canvas 2D 背景）、`graph.js`（数据转换）、`layout.js`（固定坐标布局）、`camera.js`、`route.js`、`popover.js`、`stars.js`（星空）、`anatomy.js`、`glyphs.js`、`sample-data.js`、`styles.css`（约 1740 行，唯一样式文件）
- 数据结构（**是契约，不得改动**）：`theme → idea → nodes → refs`，节点 id 稳定，连线只有 `recorded` 和 `inferred` 两种。界面不得写死主题数和步骤数
- 数据来自 `private-data/` 下三个 JS 文件（被 gitignore，**不读取其内容**）；读不到时退回 `src/sample-data.js`，顶栏显示"示例数据"
- 路由是 hash：`#/`、`#/{theme}`、`#/{theme}/{idea}`、`#/{theme}/{idea}/{step}`、`.../source/{id}`
- 动效开关有两层：首次加载读 `prefers-reduced-motion`；顶栏按钮 `#motion-toggle` 手动切换，`applyMotion()` 写入 `.app[data-motion="on|off"]`。关了之后节点和操作仍在，只是不再缓动
- 主循环在 `app.js` 的 `tick()`：只有 `state.motion` 为真才调 `background.frame()`；时间步长已限制在 0.05 秒以内
- `background.js` 的 `frame()` 每帧第一件事是 `clearRect` 整幅清空再重画（不是半透明拖尾），并已接收 `motion` 参数
- 新节点从父节点位置生出，离开的节点加 `.is-exiting` 后 280 毫秒移除，位移由 `scene.js` 的 `frame()` 以时间常数 `EASE_TAU = 0.17` 缓动
- 检查脚本：`node scripts/check.mjs`。**它只检查数据结构，不读样式**，证明不了样式没出错

### 3.2 层级（z-index）实况

这是核对时反复要用的事实。

| 层 | z-index |
|---|---|
| `#bg-canvas`、`.vignette`、`.edges`、`.edge-tags` | auto（未设） |
| 节点 `.node` | 行内 20 / 30 / 40，选中再 +20，即 20–60 |
| `.stars` | 5 |
| `.top-bar`、`.bottom-bar` | 60 |
| `.popover` | 90 |
| `.intro` 开场遮罩 | 120 |

`.app` 是 `position: fixed`，覆盖整个视口，是定位父元素；`.stage` 不创建层叠上下文。

**既有行为，不是本项目引入的，不要顺手改：** 选中的第 3 层节点 z-index 也是 60，与顶栏相同，在 DOM 中晚于顶栏，所以选中的节点可以压在顶栏上。

### 3.3 部署与私有桶

- 第二大脑不随博客一起部署。文件手动上传到私有桶 `second-brain-private`
- 博客仓库 `personal-blog` 的 `functions/second-brain/` 是登录门卫：`r2KeyFromPathname()` 把 `/second-brain/` 后的路径原样映射成桶内键；`contentTypeFor()` 对 `.css` 返回 `text/css`、`.js` 返回 `text/javascript`；**对扩展名没有白名单**，所以新增文件只要上传了就能返回，不用改门卫
- 私有内容返回 `Cache-Control: private, no-store`
- **工作副本里没有 `private-data/`**，所以不能用"同步整个目录"的方式上传，否则桶里的真实数据可能被当作多余文件删掉。**只上传改动的文件**

### 3.4 参考代码

`.voiden-ref/` 存放 Voiden 的参考代码，**只读、不进仓库、不上传 R2**。它原本只被本机的 `.git/info/exclude` 排除，换一台机器就失效，所以第一期提交 0 已把它写进 `.gitignore`。其中 `blackhole-port.js` 是一个已能跑的原生 WebGL 移植，每像素每帧最多 170 步。

## 5. 铁律

任何情况下都不得违反。需要例外，只能由老板在当前对话里明确批准，且只对这一次、这一件事有效。

1. **先评估，再动手。** 评估阶段只读：不改、不建、不删文件，不装依赖，不跑构建。
2. **不合并、不推送、不上传、不部署、不删除。** 这些永远由老板亲自批准。
3. **在独立工作副本和独立分支里改。** 开工前先看 `git status`，当前分支有未提交或未合并的改动就停下汇报。
4. **范围锁定。** 只做当期计划写明的事。发现必须改计划之外的东西，停下来问。
5. **计划与代码矛盾时，停下来汇报。**
6. **不读、不引用私有数据和密钥。** `private-data/` 只提文件名，不提内容。
7. **`.voiden-ref/` 只读。** 不拷贝其中任何内容进 `src/`，不进仓库，不上传。
8. **不引入新依赖、不加构建步骤。**
9. **所有路径保持相对（`./` 开头）。** 不出现以 `/` 开头的绝对路径，不改变任何已有文件的 URL。
10. **不确定就说不确定。** 不编造文件名、行号、数字、命令输出。

### 证据规则

1. 每个结论带依据：文件路径加行号、命令及输出、或截图文件名。
2. 区分三类陈述并标出：「看到了」（读到的代码）、「运行验证过」（实际执行并观察到）、「推测」（必须附验证方法）。
3. 检查脚本只证明它检查的范围，汇报时写明它**没有**覆盖什么。
4. 数量类断言给出统计口径。
5. **转述不等于核对。** 收到汇报后至少抽查 3 处自己确认，才能放行。

### 立即停下并汇报老板的情况

- 当前分支有未提交或未合并的改动
- 计划与代码矛盾
- 需要改计划之外的文件
- 需要新增依赖或构建步骤
- 检查脚本输出与基线不一致且原因不明
- 任何操作可能影响私有数据、线上内容或其他项目
- 同一问题修了两次仍未解决
- 你与 Claude Code 就同一问题来回 3 轮仍未对齐

## 7. 各步骤的目的与要求

每一步列出：目的、必须达到的要求、不做什么、产出。

### 步骤 0：准备（已完成）

- **目的：** 保证改动安全、可回退、起点干净。
- **要求：**
  - 原项目目录停在 `fix/edge-flow-loop` 分支，**不在那里改，也不在那里合并**
  - 建独立工作副本 `~/Documents/03-Github/Cyber-2nd-Brain-phase1`，分支 `feature/second-brain-visual-phase1`，从主分支开出
  - 修订后的计划作为这个分支的**第一个提交**（只含文档），之后才是代码提交
- **产出：** 工作副本、分支、计划提交 `54a54dd`。

### 步骤 1：评估（已完成）

- **目的：** 判断能不能做、怎么做，不动任何文件。

### 步骤 4：第二期 · 切换层级时的收拢与展开

**前提：** 第一期已通过 G3，老板已亲自看过效果。

**目的：** 只改动画的节奏，不改布局算法、不改数据、不改相机的适配规则。

**效果：** 点一个主题脑时，周围节点先向**旧层中心**收拢、变小、变淡；约三分之一秒后，新一层的节点从**新层中心**向外展开、变亮。整个过程约半秒，平稳不弹跳。返回上一层同理。点步骤、打开浮框、展开来源这些不换层的操作保持不变。关掉动效后立刻到位，无收拢、无等待。

**改哪些文件：**
- `src/scene.js`：`setLayout()` 加参数 `collapse`（默认为假，现有调用不变）
- `src/app.js`：把换层判断传给场景，并在收拢期间锁住点击
- `src/styles.css`：加一条规则，并确认关闭动效时位移也无过渡

**必须达到的要求：**
- **旧层中心与新层中心不是同一个点。** 离开的节点收拢到**旧层**的中心，新节点从**新层**的中心展开。从总览进入开发时，其余四个主题脑收向总览的总脑，问题节点从开发脑的位置展开。中心节点是布局里 `role` 为 `theme-active` 或 `core` 的那个，找不到就用画布中心 (0, 0)
- **前后两层都存在的节点**（例如被点中的主题脑本身）不走收拢也不走展开，不加 `.is-exiting`，也不加 `.is-held`，只从旧位置缓动到新位置。现有代码已是这个行为，要保证收拢逻辑不把它当成离开的节点
- 新节点先创建但加 `.is-held`（`opacity: 0`），出生位置取新层中心；记下解锁时间 `performance.now() + 340`；到时去掉 `.is-held`，新节点用现有 `EASE_TAU` 展开
- 旧节点的删除延迟由 280 毫秒改为 420 毫秒
- 点击锁：场景暴露 `isCollapsing()`，在解锁时间前返回真；`activateNode()` 开头判断，收拢期间直接返回；锁的时间不超过 400 毫秒
- 只有**换层**才走收拢：选中节点、展开来源、窗口缩放都不算。换层判断已存在于 `applyRoute()` 的 `structuralChange`（约第 385 行）
- 动效关闭（`instant` 为真）或 `collapse` 为假时走现在的路径：不加 `.is-held`，不延迟，离开的节点立刻移除
- 不加 GSAP 或任何动画库，复用现有缓动

**验收标准：**

7. **快速连续点三次不同主题：** 不出现两层节点叠在一起，不出现点不了的节点，最终停在最后一次点的那一层

### 步骤 5：第三期 · 发光环背景（Canvas 2D）

**前提：** 第二期已通过 G4。

**目的：** 加一个发光的中心物。它是一圈绿色的光，**不是引力透镜，不是黑洞，没有吸积盘，没有光线弯曲。**

**效果：** 画布正中央有一圈柔和的绿色光晕，亮度低于任何一个节点。光晕中间是空的，能看见后面的网格与星空。光沿着环缓慢流动，一圈约 16 秒，不闪烁不跳动。关掉动效后光环停在当前帧，不消失。手机上光环更小、更暗、画得更粗。**光环固定在屏幕中心，拖动、缩放画布时它留在原处。**

**改哪些文件：**
- 新增 `src/glow.js`：导出 `createGlow(ctx)`，返回 `{ frame, resize }`，约一百行
- `src/background.js`：引入并接入
- `src/app.js`：主循环的补画逻辑（`index.html` **不用改**）

**必须达到的要求：**
- **画法：** 全部用 Canvas 2D 径向渐变，不用着色器、不用 WebGL。中心取画布中心（屏幕坐标，不加相机偏移），半径取较短一边的约四分之一，手机（较短边小于 560）再乘 0.8
- **两层：** 外层是一个很宽、很淡的径向渐变（透明 → 绿色淡色 → 透明），宽度约半径的一半，**完全不动**；内层是一圈 1.5 像素的细线，颜色取 `--green`，透明度约 0.35
- **外层光晕预渲染到一张离屏画布**，在 `resize()` 里画一次，每帧只把离屏画布整幅贴上去，再画移动的亮弧。离屏画布的尺寸要与主画布的设备像素尺寸一致，贴图时不缩放
- **流动：** 把环分成约 48 段短弧（手机 24 段），每段亮度由它与一个缓慢移动的角度之间的距离决定；角度每秒增加约 0.4 弧度。这是唯一随时间变化的量
- **分辨率跟着 `background.js` 走**，设备像素比上限取 2，**不另设 1.5**。光环和背景共用同一块画布，分辨率由那块画布决定，光环没法自己降
- **颜色从 `tokens.css` 读，不写死。** 读取时必须 `trim()`（自定义属性的值带前导空格），读到的是十六进制，要转成 rgb 再拼透明度。只在 `resize()` 里读一次，不要每帧读
- **清除策略只有一种：** `background.js` 的 `frame()` 每帧用 `clearRect` 整幅清空，光环排在网格、微粒、0/1 之后画，直接画在清空后的画布上。**不自己清任何区域，不用 `lighter` 叠加**，不需要独立的 `<canvas>`
- **`frame()` 已有 `motion` 参数**（第三个），不用新增。为假时角度不增加，光环画出来但停住
- **时间步长不用改，也不要在光环里再写一个限制。** `tick()` 里已是 `Math.min((now - last) / 1000, 0.05)`，切到后台再回来时单帧最多推进 0.05 秒，角度不会跳变
- **主循环改法（以此为准，不要混用）：** 动效开着时每帧都调 `background.frame()`；动效关着时，**只在下面四个时机各补画一帧**，其余时候不调：
  1. 开转关：`applyMotion()` 把动效从开改成关的那一次，补画一帧
  2. 窗口缩放：现有 `resize` 监听调 `background.resize()` 之后补画一帧（缩放会清空画布，否则光环停在旧位置）
  3. 页面重新可见：监听 `visibilitychange`，`document.hidden` 由真变假且动效关着时补画一帧；后台期间不画
  4. 光环初始化：页面首次进入、光环刚创建完时补画一帧（否则系统开启"减少动态效果"、动效一开始就是关的时，画布上永远没有光环）
- **降级：** 动效关闭或系统开启"减少动态效果"：画一帧、角度固定、之后不再进入绘制。`canvas.getContext("2d")` 失败：不画光环，其余页面照常，不报错、不阻断加载
- 不加 WebGL 库、不加物理库、不复制 `.voiden-ref/` 里的任何内容

**验收标准：**
1. 共同约束全部满足
2. 画面中央有一圈绿色光晕，亮度低于最暗的主题脑；节点标签、连线、星空仍能清楚辨认
3. 光环中间是空的，能看见背后的网格；没有黑色圆盘、吸积盘、被弯曲的星光
4. 关掉动效：光环停住不再流动；性能面板里关闭后脚本不再持续占用 CPU。再打开，从停住的那一帧接着流动，不跳变
5. 系统开启"减少动态效果"后刷新：光环从一开始就是静止的，**而且画布上确实有这一圈，不是空白**
6. 切到别的标签页再回来：离开期间不绘制，回来后恢复，角度没有跳变
7. 缩放窗口、旋转手机：光环跟着重新居中，不留旧的一帧，不出现一帧全黑
8. **低端性能：** Chrome 开发工具 4 倍 CPU 节流，390×844，走完"总览 → 主题 → 问题 → 步骤 → 返回"，点击到画面响应不超过一拍。做不到就把段数再减半、流动改为每两帧画一次，直到做到
9. 光环不挡任何操作：拖动、缩放、点节点、点星空都与第二期一致
10. 拖动、缩放画布时光环留在屏幕中心不动，不跟着节点跑，不抢戏，帧率不比第二期更差

**回退：** 删掉 `src/glow.js`，恢复 `src/background.js`。**`src/app.js` 只撤销第三期的改动**（主循环补画逻辑与 `visibilitychange` 监听），保留第二期加的换层判断与点击锁。**不要把 `app.js` 整个文件恢复到第三期之前，那会把第二期一并撤掉。**

## 8. 已知陷阱清单

这些都是真实发生过的错误，核对时要主动检查。

**计划本身的错误（修订两次才干净）：**
1. **"后一期不修改前一期的文件"与事实矛盾**：第二期和第三期都要改 `app.js`。后果：第三期回退时可能把第二期一并撤掉
2. **第三期写了"设备像素比上限 1.5"**：光环与背景共用一块画布，光环自己降不了分辨率。这条做不到
3. **清除策略自相矛盾**：先写"每帧清掉自己的区域"，又写"用 `lighter` 叠加不清"。成立的前提是 `background.js` 整幅重画（实测成立）
4. **主循环改法前后矛盾**：一处说"无论开关都调一次"，一处说"关闭后只在转换帧调用"。以后者为准
5. **"删掉旧 `:root`"漏掉两个布局变量**：`--inset-top`、`--inset-bottom` 不被任何 CSS 引用，只被脚本读取，删掉会让星空与浮框定位退回写死的默认值，窗口变窄、顶栏换行后偏移
6. **颗粒 `z-index: 4` 的依据不成立**：节点 20–60、星空 5，但连线与连线标签是 auto，4 会盖在它们上面，让线显脏
7. **"改 `--green` 全局跟着变"不可达**：连线、光晕、边框用的是写死的 rgba 或 `--green-mid`，只有 9 处直接引用 `--green`
8. **颜色字面量例外实际 135 处**，计划原先只列了 5 类、覆盖约一半，按"对不上的算不通过"第一期会直接失败。所以验收改成集合差集
9. **令牌数量写错**：颜色令牌是 12 个，不是 11 个
10. **`--star` 与 `.star` 上的局部变量重名**，`:root` 里定义会被覆盖，是死令牌
11. **效果描述承诺过头**："深浅现在一致了"、"字号与间距落在固定的几档上"。实际只替换了 12 处颜色，字号间距只匹配约一半，视觉不变
12. **第二期"中心节点"没说清是新层还是旧层**
13. **`.voiden-ref/` 只被本机的 `.git/info/exclude` 排除**，不随仓库同步

**核对与验证中的陷阱：**
14. **`check.mjs` 不读样式**，通过它证明不了样式没出错
15. **基线截图必须避开开场动画**（约 3.4 秒），原先那 8 张是动画进行到一半时截的，无法比较
16. **背景粒子会动**，对比截图时要先隐藏 `#bg-canvas`，否则差异永远不为零
17. **示例数据下星空与断语卡根本不存在**（没有 `lessons.js` 时 `createStars` 直接返回 noop），基线截不到，只做静态代码核对

19. **颜色引用统计要有口径**：147 处是 `:root` 之外 `styles.css` 里的字面量；另有 3 处在 `background.js`（网格线、微粒、0/1），属于动画数据，不归第一期

**部署与环境的陷阱：**

## 9. 核对汇报的方法

收到 Claude Code 每个阶段的汇报后，按下面做，再决定放行或退回。

### 通用步骤

1. **对照验收标准，逐条检查**汇报里是否都有依据。没依据的算未通过
2. **抽查至少 3 处**，自己去代码或产物里确认，不要只信结论
3. **检查"全部通过"的覆盖范围**：它验证了什么，没验证什么

|---|---|
